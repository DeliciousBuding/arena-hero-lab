# Arena Hero Lab contributor rules

## Scope

This repository contains independent Python packages and one browser application. Keep
changes inside the smallest owning package and preserve one-way dependencies.

## Read first

1. `README.md`
2. `docs/architecture.md`
3. The package README for the component being changed
4. `apps/leaderboard-web/AGENTS.md` for web work

## Architecture boundaries

- `arena-hero-sim` must not import benchmark, research, web, or agent packages.
- `arena-hero-bench` may depend on `arena-hero-sim` and owns artifact/run manifests.
- `arena-hero-research` may depend on sim and bench; optional heavy analysis libraries stay here.
- `leaderboard-web` reads generated artifacts and must not recompute authoritative rankings.
- Do not introduce a shared mutable database between packages.
- New TypeScript is for browser code or generated types only. The existing TypeScript
  converter is a migration oracle and must not become a second production pipeline.

## Generated data and reproducibility

- `apps/leaderboard-web/src/data/bench.json` is generated by the Python converter.
- The Python and TypeScript converters must remain differentially equivalent until the
  oracle is retired in a reviewed change.
- Artifact identities use SHA-256 of canonical content. Git object identifiers and
  artifact SHA-256 values are separate fields.
- `partial` and `failed` artifacts are never publishable.

## Required checks

```bash
uv sync --locked --all-groups
uv run ruff format --check .
uv run ruff check .
uv run ty check packages scripts apps/leaderboard-web/scripts/release.py
uv run pytest -q
pnpm install --frozen-lockfile
pnpm lint
pnpm build
python scripts/check_public_surface.py
git diff --check
```

Do not skip or weaken tests to make a change pass.

## Repository hygiene

- Never commit credentials, private infrastructure details, local absolute paths, or raw
  private datasets.
- Use repository-relative paths and environment-neutral examples.
- Keep `.worktrees/`, dependency directories, caches, and build output untracked.
- Publishing, remote repository changes, and default-branch changes are separate release
  operations; ordinary development changes must not perform them.
